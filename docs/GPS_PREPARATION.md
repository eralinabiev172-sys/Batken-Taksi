# Подготовка GPS-оборудования BusWay KG (Этап 4)

## Статус

Документ подготовки к Этапу 4 (аппаратный GPS). Реальные устройства, SIM и тарифы не закуплены. Дорожные тесты не проводились. D-133 остаётся открытым.

## 1. Требования к трекеру (из MASTER_TZ / SECURITY / ARCHITECTURE)

- Единственный production GPS-source (D-003); браузер/телефон не допускаются.
- Целевая передача позиции каждые 2 секунды во время работы (D-006).
- Локальный offline buffer на устройстве.
- Настраиваемый собственный server endpoint, документированный протокол, совместимость с Traccar.
- Уникальная конфигурация устройства, смена заводских паролей.
- TLS с проверкой сервера и per-device secret/certificate, если модель поддерживает; иначе private APN/VPN + сетевой allowlist (D-016, SECURITY §4).
- IMEI-only через открытый plain TCP/UDP не допускается для production.
- Возможность блокировки/отзыва устройства и безопасной замены.
- Удалённые команды трекерам выключены в MVP (D-122).

## 3. SIM и покрытие

- Оператор, bands и тариф выбираются после теста покрытия Кара-Булак ↔ Баткен (D-120).
- Ориентировочный расход: ~1.5 позиций/сек для 3 автобусов ≈ 5400 позиций/час при 2 сек; каждый пакет ~100–300 байт → ~1–2 МБ/час на автобус при непрерывной работе. Месячный трафик на устройство оценивается в 0.5–2 ГБ (ориентировочно, зависит от протокола и частоты).
- Private APN/VPN предпочтителен; при отсутствии TLS/per-device credential — обязателен allowlist (D-016).
- IMEI-only через открытый plain TCP/UDP для production не допускается (SECURITY §4).

## 4. Бюджет (ориентировочно, не подтверждён)

- 3 трекера: цена зависит от модели и поставщика (ориентир $30–$80 за устройство).
- SIM: ежемесячно по тарифу оператора КР (ориентир $3–$10/мес за SIM).
- Сервер Traccar: существующий одиночный сервер (D-101), бюджет до $10/мес (D-012/production budget).
- Установка/монтаж: отдельно, по локальным расценкам.

Все цены — ориентировочные, требуют подтверждения перед закупкой (D-012).

## 5. Traccar (изолированная конфигурация)

- Self-hosted Traccar на одиночном сервере (D-114), постоянная БД (не in-memory).
- Изолированная конфигурация: `infra/traccar/docker-compose.example.yml`, `infra/traccar/traccar.xml.example`.
- Не запускать без отдельного разрешения; не использовать реальные credentials в репозитории.
- Только порт выбранного device protocol открыт наружу; UI/API — private network/localhost.
- Forwarding в Fastify аутентифицирован (отдельный секрет), private network.
- Remote commands выключены (D-122).
- Auto-registration unknown devices выключена.
- Retry Traccar ограничен; постоянная БД + reconciliation обязательны (ARCHITECTURE §7).

## 6. Проверка контракта Traccar → Fastify

- Endpoint: `POST /internal/v1/gps/positions` (private, gateway auth через `X-Gateway-Secret`).
- Нормализованная запись: gatewayPositionId, deviceExternalId, measuredAt, receivedAt, sequence, position, speedMps, headingDeg, accuracyM, attributes.
- Dedupe по gateway position ID или устойчивому составному ключу.
- Валидация timestamp, sequence, координат, скорости, аномалий.
- Идемпотентный ответ.
- Сохранение rejection reason без утечки секретов.
- Принятая GPS-точка сама никогда не включает публичность (проверка grant при выводе).

## 7. Пилотный план (не проводить без оборудования)

1. Приобрести 2–3 пилотных трекера (D-124: минимум 2–3 варианта до массовой закупки, если владелец не утвердит иной план).
2. Проверить exact model/order code/firmware и bands (D-115).
3. Установить SIM, настроить APN/TLS/per-device credentials (D-016).
4. Установить Traccar, настроить протокол/security, открыть только device protocol port.
5. Настроить tracker→bus assignment через admin.
6. Проверить 2-second mode: реальный трекер передаёт позиции ~2 сек.
7. Водитель включает публичный показ; пассажир видит настоящий автобус и движение, включая стоянку на автовокзале и обратный рейс.
8. Проверить last update и freshness.
9. Проверить ручное отключение/истечение grant → автобус не публикуется.
10. Потеря сети ≥30 минут → проверка offline buffer и delayed upload.
11. Forwarding outage дольше retry queue → восстановление через reconciliation без дубликатов.
12. Delayed-позиция не заменяет новую live-позицию и не возвращает отключённый автобус.
13. Проверить отключение питания, SIM/GNSS/сети, restart компонентов.
14. Проверить минимум 2–3 пилотных устройства/варианта.

Ни один hardware-тест не получает PASS без физического оборудования и сохранённых результатов.
