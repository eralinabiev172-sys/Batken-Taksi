# Публичная карта на реальном API (режим разработки)

По умолчанию сайт работает на демо-данных (Этап 2). Реальный режим включается только для **публичной карты**; экраны водителя и администратора пока остаются демо и сохраняют метку «демо».

## Как включить
1. Запустить API (Fastify) на `127.0.0.1:3001` с настоящей БД.
2. В `apps/web` запустить dev-сервер с переменной `VITE_USE_REAL_API=true`. Он проксирует `/api` и `/ws` на `127.0.0.1:3001` (см. `vite.config.js`).
3. Для сборки за reverse proxy задать `VITE_API_BASE_URL` и `VITE_WS_URL` (по умолчанию тот же origin: `/api/v1` и `/ws/v1/live`).

## Что берётся с сервера
- `GET /api/v1/routes` — маршруты, направления и остановки (только публичные id; линия маршрута `null`, пока геометрия не утверждена, D-126).
- `GET /api/v1/vehicles/live` — автобусы с действующим grant водителя.
- `WS /ws/v1/live` — `snapshot`, `vehicle.position`, `vehicle.removed`. Клиент переподключается с задержкой 1–10 с и после каждого подключения заменяет состояние новым snapshot.

## Проверки
- Unit: `apps/web/src/services/realTransportService.test.js`.
- Браузер (Chrome, реальный API и изолированная БД): из `apps/web` запустить `npx playwright test -c playwright.real.config.js`; нужен запущенный контейнер `busway-test-postgres-iso`. Тест создаёт и удаляет только свои строки.

## Известные ограничения
- Публичное имя автобуса пока производное от `vehiclePublicId` («№ AB3D»). Нужно решение владельца, как называть автобусы пассажирам.
- Строка на кыргызском `liveCoordinates` написана без носителя языка и требует проверки.
- У публичных эндпоинтов нет rate limit (SECURITY.md §8); добавить до публикации в интернет.
